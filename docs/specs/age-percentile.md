## 1. Discovery（なぜ作るか）

### 1-1. 課題・仮説 ⬛
- 「答え型ツール」は AI チャットに需要を侵食される（2026-06-10 戦略修正）。
  攻めは**体験型**＝「自分を測る・遊ぶ・シェアする」。
- AdSense 監査で唯一「独自データ」と評価されたのが birth-year の統計。
  **公的統計 × 自分ごと化**が当サイトで実証済みの唯一の勝ち筋。
- 仮説: 「日本人の平均年齢は◯歳」は AI が答える。
  **「あなたより年上は◯◯万人」は AI が即答できず、その場で計算して見せる体験になる。**

### 1-2. 競合 ⬛
- 年齢計算ツールは飽和（当サイトの age.html 含む）。だが**人口の中の位置を出すもの**はほぼ無い。
- 人口統計サイト（政府・自治体）は表の提示のみで、自分ごと化しない。

### 1-3. ターゲット 🔴
- 案: ①SNSで話題を共有したい層（20〜40代） ②自分の年齢を意識するイベント時（誕生日・年度替わり）
- **決めること: 主ターゲットを1つに絞るか、絞らないか。**

### 1-4. 成功の定義 / 完成の定義 🔴 ★最重要
> **これが無いのが mini-tools が終わらない原因。** 今回は必ず先に決める。
- 「完成」= 何が満たされたら手を止めるか（例: リリース基準セクションの全項目 green）
- 「成功」= 公開後に何が起きたら成功か（例: Search Console でインプレッションが立つ／
  自分がスマホで見て面白いと思う／誰かに共有したくなる）
- **決めること: 成功指標を「数字」で置くか「自分の実感」で置くか。**
  - 案A: 数字（公開30日でインプレッション◯以上）→ 客観的だがトラフィックが少ないと判定不能
  - 案B: 実感（自分が友人に送りたくなるか）→ 検証器としては弱いが、この規模では現実的
  - 案C: 両方（実感でリリース判断、数字は3ヶ月後の振り返りに使う）← 推奨

## 2. Define（何を作るか）

### 2-1. ユーザーストーリー 🔵
1. 生年月日を入れると、日本の人口の中で自分がどの位置かがすぐ分かる。
2. 「同い年は何人いるか」「同学年は何人か」が分かる。
3. 結果をワンタップでコピーして SNS に貼れる。

### 2-2. スコープ（v1でやること）🔴確認
- 生年月日（または年齢）入力 → 人口内の位置を表示
- 出力項目（下の 3-2 参照）
- 結果テキストのコピー / X 共有リンク
- 統計の早見表を**静的HTML**で出力（SEO・#62 注意②）
- 解説（この統計は何か・出典・注意）＋ FAQ ＋ 関連ツールリンク

### 2-3. 非スコープ（v1でやらないこと）⬜
- シェア**画像**生成（Canvas）→ IDEAS #38 が来てから
- 都道府県別 / 職業別 / 年収など他統計との掛け合わせ → 第2弾以降
- 将来推計（何年後に上位◯%になるか）→ 面白いが v1 では出さない
- ログイン・保存・履歴

### 2-4. データ 🔵
- 出典: 総務省統計局「人口推計」年齢各歳別人口（男女別）。
- 形式: `js/lib/population-data.mjs` に**静的データとして同梱**（外部API依存なし・0円・端末内処理を維持）。
- 更新: 年1回、このファイルの差し替えのみで完了する設計（#37 の「毎年更新で放置が崩れる」を回避）。
- **リスク**: このコンテナから e-Stat のデータを取得できない可能性。
  取得不可の場合は**5歳階級の公表値で代替**し、精度を落として先に完成させる（後で各歳別に差し替え可能な構造にする）。
  → 代替時は画面に「5歳階級の概算」と明記する。

## 3. Design（どう見せるか）

### 3-1. デザインの方向 🔴 ★
既存サイトは実用ツール向けの落ち着いたデザイン（`style.css`: 白カード・青アクセント・最大幅720px）。
本ツールは**体験型で、結果画面がシェアされる＝それ自体が商品**。ここで方針が分かれる。

- **案A: 既存デザインに完全に合わせる** … サイトの一貫性◎・工数最小。ただし地味でシェアされにくい。
- **案B: 結果部分だけ作り込む**（大きな数字・視覚化バー・強調色）… 一貫性を保ちつつ体験型らしさを出す。**推奨**
- **案C: このページだけ別デザイン** … インパクト最大だが、サイトの統一感とAdSense的な「まとまり」を損なう。

**決めること: A / B / C のどれか。**

### 3-2. 結果画面に出す項目 🔴
研究知見（IDEAS #62 関連）を反映した案:
1. **「同世代100人のうち、◯人があなたより年上」** ← ％でなく**自然頻度**で出す（Gigerenzer。％は理解されにくい）
2. あなたより年上は **◯◯万人** / 年下は **◯◯万人**
3. 同い年は約 **◯◯万人**
4. **同学年**は約 **◯◯万人**（早生まれ考慮）← 日本特化
5. 男女別の内訳
6. 「日本の人口のうち、上から約 **◯◯番目**」← インパクト枠（Peak-End：**最後に一番強い数字**を置く）

**決めること: ④同学年 と ⑤男女別 を入れるか。**（推奨: どちらも入れる）

### 3-3. 情報設計 🔵
入力 → 結果（上記の順）→ コピー/共有 → 解説 → 早見表 → FAQ → 関連ツール
※ 結果は入力と同時にリアルタイム更新（差別化原則②）

### 3-4. コピー・文言 🔵
- 断定的に書く（IDEAS #66「診断系は断定的に、実害系は補助的に」）。
- ただし**統計の限界は明記**（推計値である・基準日・概算である旨）。

### 3-5. アクセシビリティ / レスポンシブ 🔵
- ラベルと入力の関連付け、キーボード操作、コントラスト比、スマホ幅での可読性。既存ページと同水準。

### 3-6. 名前とURL 🔴
- 案: `age-rank.html`（分かりやすい） / `population-rank.html`（正確） / `age-percentile.html`（検索向き）
- ページタイトル案: 「日本であなたは何番目？ 年齢の人口ランキング」
- **決めること: ファイル名とタイトル。**（推奨: `age-rank.html`）
